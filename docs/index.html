카드 게임으로 푸는 최장 증가 부분수열

같은 수열을 두 방법으로 한 단계씩 풉니다. 왼쪽은 표를 채우는 동적계획법, 오른쪽은 카드를 쌓는 페이션스 정렬입니다. 단계마다 무엇을 했고 왜 그런지는 오른쪽 여백의 번호 주석에 적었습니다.

최장 증가 부분수열(LIS)은 수열에서 순서는 그대로 두고 몇 개를 골라 뒤로 갈수록 엄격히 커지게 만들 때 가장 긴 것입니다. 10, 3, 11, 5, 8, 6, 1, 2, 7에서는 3, 5, 6, 7(길이 4)입니다.

03왜 이렇게 되는가

    

      

        
복잡도 비교

        

          
DP페이션스 정렬

          
            
시간Θ(n²), 모든 경우O(n log n) 최악, 더 정확히 O(n log L)

            
공간Θ(n): dp[], prev[]Θ(n): top[], back[]

            
비교 횟수항상 n(n−1)/2카드마다 이분검색 ⌈log₂(더미 수+1)⌉번 이하

          
        

        
DP는 칸 i를 채울 때 왼쪽 i−1칸을 전부 비교하므로 1 + 2 + … + (n−1) = n(n−1)/2번이고, 입력과 상관없이 늘 같습니다. 페이션스는 카드마다 맨 윗장(더미 수 L개, L ≤ n)에서 이분검색만 하므로 n·log L 정도입니다.

      

      

        
더미 개수가 왜 답인가

        
    
          
  1. 답 ≤ 더미 수. 한 더미 안의 카드는 위로 갈수록 작거나 같습니다(나중 카드가 자기 이상인 카드 위에만 올라가니까). 그래서 증가 부분수열은 한 더미에서 카드를 두 장 이상 쓸 수 없습니다.
    2. 
          
  2. 답 ≥ 더미 수. 카드를 놓을 때 왼쪽 더미의 맨 윗장(자기보다 작고 먼저 나온 카드)을 화살표로 가리킵니다. 마지막 더미에서 화살표를 따라가면 더미마다 한 장씩, 길이가 더미 수인 증가 부분수열이 나옵니다.
    3. 
        

        
둘을 합치면 더미 수 = LIS 길이입니다.

      

      

        
실제로 쓰이는 곳

        
Git의 git diff --patience는 두 파일에서 한 번씩만 나오는 줄을 짝지은 뒤, 서로 엇갈리지 않는 가장 많은 짝을 고를 때 이 페이션스 정렬로 LIS를 구합니다. 빈 줄이나 중괄호처럼 흔한 줄에 엉뚱하게 맞춰지는 일이 줄어서, 사람이 읽기 좋은 diff가 나오는 경우가 많습니다.

        
출처: git-diff 공식 문서, J. Coglan, The patience diff algorithm (2017)
